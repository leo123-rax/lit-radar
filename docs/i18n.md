# Language and country layer (`litradar/i18n.py`)

The corpus is global: Chinese, Japanese, Korean, Russian and Latin-script research all land in the
same database. This layer answers two questions about every stored paper, offline and for free, and
adds an optional third that costs money:

| Question | Where the answer lives | Cost |
|---|---|---|
| What language is it written in? | `papers.extra_json` -> `lang` (ISO 639-1) | free, stdlib |
| Which countries are its authors in? | `papers.extra_json` -> `countries` (ISO 3166-1 alpha-2 list) | free, stdlib |
| What does the non-English title/abstract say in English? | `translations` table | Claude API, opt-in |

Dashboards and trend queries read the two `extra_json` keys; nothing else in the pipeline depends on
this module, so it can be run, re-run or skipped at any time.

```bash
litradar tag --since 365d              # tag everything published in the last year
litradar tag --since 30d --translate   # ... and translate the non-English ones (needs ANTHROPIC_API_KEY)
litradar tag --since 365d --json       # machine-readable histograms on stdout
litradar tag --since 365d --check      # read-only: histograms of what is tagged + a warning if rows lost their tags
```

`tag` is idempotent: tags are recomputed from title / abstract / authors / affiliations every time,
never from the previous tags, so re-running after editing the lookup tables simply refreshes them.
Tags are also **volatile** - see (d): every ingest that touches a paper erases them, so `tag` belongs
after every `run`.

## (a) `detect_language(text) -> str`

Returns one of `en zh ja ko ru es pt fr de other`. No dependency, no model, ~1 µs per title.

1. **Script ranges** decide the family. Letters are counted per Unicode block (Latin, CJK ideographs,
   kana, Hangul, Cyrillic, everything else). CJK/kana/Hangul counts are weighted x3 against Latin
   letters, because one ideograph carries about as much meaning as a Latin word - that is what keeps
   `CRISPR-Cas9介导的基因编辑技术研究进展` Chinese while leaving
   `Spatial transcriptomics of liver cancer (肝癌空间转录组研究)` English.
2. Within East Asian text: any kana -> `ja`; Hangul-dominant -> `ko`; a kana-free string that contains
   a Japanese-only character form -> `ja` (post-war *shinjitai* such as 発 経 対 図 変 気 伝 検 験 薬,
   whose Simplified and Traditional Chinese counterparts are different code points, plus *kokuji*
   like 働 込 畑); otherwise `zh`. Cyrillic -> `ru`. A majority of letters outside all of these blocks
   (Greek, Arabic, Devanagari, ...) -> `other`.
3. **Latin script** is resolved by weighted stopword counts: a stopword unique to one language scores
   2, a shared one 1, plus small bonuses for diacritics (`ñ` -> es, `ã/õ` -> pt, `ß/ü/ö/ä` -> de) and
   elisions (`l'`, `d'` -> fr; `dell'`, `nell'` -> it). Italian and Dutch stopword sets exist only so
   that Italian and Dutch text lands in `other` instead of being mistaken for es/fr/de.
4. **English is the prior** for scientific text. Another language wins only with real evidence:
   score >= `MIN_SCORE` (4.0), at least `MIN_MARGIN` (2.0) ahead of the next non-English candidate and
   `MIN_MARGIN_EN` (3.0) ahead of English. Latin and loan phrases that are ordinary English usage are
   stripped before scoring (`van der Waals`, `de novo`, `in vitro`, `in vivo`, `in situ`, `per se`,
   `et al`, ...), because without that a physics title about van der Waals ferromagnets scores as
   German and a protein-design title as Spanish.

Known limits, by design (each one is a probe in `tests/test_i18n.py::LANG_CASES`, so the behaviour is
pinned, not assumed):

* **Latin-script languages without a stopword set here fall back to `en`, not `other`** - Polish
  (`Badanie ekspresji genów w raku piersi`), Turkish, Indonesian, Vietnamese, Czech, ... There is no
  evidence against the English prior, so the prior wins. Italian and Dutch are the exceptions: they
  have stopword sets only so that they land in `other` instead of es/fr/de.
* A short non-English title with no stopwords (two or three content words) likewise stays `en`.
* A Latin-script non-English **title with an English abstract** is tagged `en` (`paper_language`
  scores title + abstract together; bilingual Latin-American journals do this). A CJK or Cyrillic
  title decides on its own, so the Chinese-title / English-abstract pattern is still `zh`.
* **Kanji-only Japanese without any shinjitai form is `zh`** (`肺癌患者`); with one it is `ja`
  (`遺伝子発現解析`). Traditional and Simplified Chinese are both `zh`.
* Serbian/Macedonian in Cyrillic report as `ru`; Greek, Arabic, Thai, Devanagari etc. are `other`.

If a language graduates to its own code, add a stopword set and a test case - nothing else changes.

## (b) `country_of(paper) -> List[str]`

Returns ISO 3166-1 alpha-2 codes, most frequent first (ties alphabetical), empty when unknown. It
accepts a `Paper`, a `papers` row from the store, or a plain dict. `country_counts(paper)` gives the
raw per-country author counts behind the ordering.

Two sources of truth, in order:

1. **OpenAlex institution country codes** - exact, used alone when present. Read from
   `authors_json[].institutions[].country_code` and from `extra_json.institution_countries`.
2. **Affiliation strings** - every distinct string from `affiliations_json` plus each author's own
   `affiliation`, matched against the bundled lookup in `litradar/i18n_data.py`:

   * ~400 country names: English, native and adjectival spellings (`China`, `P. R. China`,
     `Deutschland`, `Türkiye`, `Chinese`, `Brasil`).
   * First-level regions: all 34 Chinese provinces/municipalities/autonomous regions, US states,
     Canadian provinces, Australian states, German Länder, Indian states, Japanese prefectures,
     Korean provinces, Brazilian states, and distinctive European regions.
   * ~900 research cities, deliberately dense for China (Guangzhou, Shenzhen, Hangzhou, Wuhan,
     Chengdu, Suzhou, Hefei ... including district names like Pudong and Zhangjiang), Japan, Korea,
     India and Latin America.
   * ~1,000 institutions, including the Chinese ones that appear without a city or country:
     `Chinese Academy of Sciences`, `Chinese Academy of Medical Sciences`, `Tsinghua`,
     `Peking University`, `Fudan`, `Zhejiang University`, `Shanghai Jiao Tong`, `Sun Yat-sen`,
     `BGI`, `Westlake`, `ShanghaiTech`, `SUSTech`, plus the giveaway patterns
     `State Key Laboratory`, `Key Laboratory of`, `... Affiliated Hospital of ...`, `People's Hospital`.
   * Case-sensitive acronyms (`USA`, `UK`, `BGI`, `RIKEN`, `KAIST`, `CNRS`, `DKFZ`, `WEHI`, ...).
   * CJK and Cyrillic spellings matched on the raw text (`中国科学院`, `東京大学`, `서울대학교`,
     `Московский государственный университет`).
   * Trailing ISO alpha-3 codes (`..., Karaikal, IND`) and, as a last resort only, a trailing US
     state code or a `TX 77030`-style state+ZIP.

Matching rules that keep it honest: phrases are accent-folded and matched on word boundaries,
**longest match wins and the matched span is consumed**, so `Chinese University of Hong Kong` is `HK`
(never also `CN`), `Northern Ireland` is `GB` (never `IE`), `London, Ontario` is `CA` (never `GB`),
`New England Biolabs` is `US`, `Niger Delta University` is `NG`, and `Hong Kong University of Science
and Technology (Guangzhou)` is `["HK", "CN"]` - both, correctly. Genuinely ambiguous names are mapped
to `None`: recognised, consumed, but no code assigned (`China Medical University` exists in Taichung
and in Shenyang; bare `Cambridge`, `Georgia`, `Santiago`, `San Jose`, `Santa Cruz`, `La Paz`, `EMBL`,
`CEA`, `IIT` likewise). **Language-level phrases are never codes**: `Hospital Universitario` is Spanish,
not Spain (named Spanish university hospitals are listed individually; a Monterrey one resolves to
`MX` via its city), and `Chinese Medicine` / `Traditional Chinese Medicine` is a discipline, not a
place, so a Hong Kong or Taiwan school of Chinese medicine never leaks `CN` into a China trend - the
mainland ones still resolve through their city, province or country. An affiliation that matches
nothing yields `[]` - the layer never guesses.

Adding an entry: pick the most specific spelling, confirm it is not also a common word or a place in
a second country, add it to the right table in `litradar/i18n_data.py`, and add a case to
`tests/test_i18n.py` if it is a new *kind* of pattern. Keys are accent-folded before merging, so two
spellings can collapse onto one key; the first definition wins and a later one with a different code
is dead data. `i18n.PHRASE_COLLISIONS` lists any such pair and a test asserts it is empty.

Known leak left in place: `State Key Laboratory` maps to `CN` because it is a mainland giveaway in the
overwhelming majority of strings, but Hong Kong and Macau host a few State Key Laboratories too, so
`State Key Laboratory of ..., Macau University of Science and Technology, Macao` yields `["CN", "MO"]`.

## (c) `translate_titles(store, since, model, api_key)`

Opt-in English translations of non-English titles and abstracts, stored in `translations`:

```sql
CREATE TABLE IF NOT EXISTS translations (
  paper_id TEXT PRIMARY KEY, lang TEXT, title_en TEXT, abstract_en TEXT, model TEXT, created_at TEXT
);
```

* Runs **only** when `ANTHROPIC_API_KEY` is set (or a client is injected). Without a key it returns
  `{"status": "skipped", ...}` and never imports the SDK.
* `anthropic` stays an optional extra (`pip install 'lit-radar[llm]'`); it is imported inside the
  function, and a missing package raises one clear error instead of breaking any other command.
* Candidates are the papers in the window whose `lang` is not `en` and that have no row in
  `translations` yet, so re-running only picks up what is new or previously refused.
* All candidates go into **one Message Batches request** (50% cheaper, polled on a wall-clock
  deadline of `max_wait_seconds`, default 1 h), with **structured JSON output** (`title_en`,
  `abstract_en`, `language`) so nothing has to be parsed out of prose. `use_batch=False` translates
  synchronously, which is handy for a handful of papers.
* `output_config = {"format": {...}, "effort": "low"}` and `max_tokens = 16000`: on current models
  thinking is always on and its tokens count against `max_tokens`, so a long abstract plus reasoning
  could otherwise stop with `max_tokens` on every run and never be stored. Low effort keeps the
  reasoning short (translation does not need it); the generous ceiling leaves room. Pass
  `effort=None` for a model that does not accept `output_config.effort`.
* The rubric sits in a system block with `cache_control` (`ttl: "1h"` in the batch path, because
  batches outlive the 5-minute cache). Honest footnote: the rubric is far below the minimum cacheable
  prefix, so caching is a no-op until the prompt grows; it is kept for parity with `rank/llm.py`.
* **Never raises for API, network or model failures.** Check `report["status"]`:
  `ok` | `skipped` (no key, SDK never imported) | `incomplete` (not `ended` before the deadline;
  nothing stored; `processing_status` and `waited_seconds` say how far it got) | `error` (an SDK/API
  exception - 401, 429, 529, connection reset ... - with `report["error"]` = `ExceptionType: message`;
  rows saved before the failure are kept). Per-paper outcomes are counted in `translated`,
  `refused_or_invalid` (`stop_reason == "refusal"` or non-JSON), `truncated` (`stop_reason ==
  "max_tokens"`, shown separately so a paper that truncates every run is visible) and `errored`
  (`result.type` errored / canceled / expired). Refused, truncated and errored papers stay candidates
  for the next run. The one deliberate exception: an API key is set but the optional `anthropic`
  package is not installed -> `RuntimeError` with the pip hint, so a misconfigured deployment is loud.
* The model comes from `Settings.llm_model` (`LITRADAR_LLM_MODEL`, default `claude-opus-5-5`).

`translations_for(store, ids)` returns `{paper_id: {lang, title_en, abstract_en, model}}` for digests
and dashboards.

## (d) `tag_store(store, since)` and `histograms(store, since)`

`tag_store` writes `lang` and `countries` into `papers.extra_json` (other keys in that JSON are
preserved) and returns the histograms it just computed. `histograms` reads already-tagged papers
without rewriting them - that is what a dashboard or a trend job should call. Both take `since` /
`until`; `since` also matches undated papers by `first_seen`, the same window rule the digest uses.
`countries` counts a paper once per distinct country, `primary_countries` only its first (dominant)
country, and papers with no country are counted under `??`. Both walk the table in `rowid` chunks
(`chunk_size`, default 5,000) with a commit per chunk, so a multi-year corpus never sits in memory.

**Tags are volatile.** `Store.upsert_paper` rewrites the whole `extra_json` column on conflict
(`extra_json = excluded.extra_json`), so any paper a later run fetches again loses `lang` and
`countries` - silently, and for trend queries that shrinks the tagged denominator after every weekly
run. Three things cover it:

* `tag_store(store, updated_since=<timestamp>)` re-tags every row whose `updated_at` is at or after
  that timestamp, whatever its publication date - pass the run's start time right after the ingest
  (wiring snippet 2 below). It combines with `since` / `until`.
* `histograms()` returns `untagged` (papers in the window without a `lang` key). When it is > 0 the
  other numbers under-count; `litradar tag --check` prints the histograms and a `WARNING` on stderr
  in that case, and the digest snippet below does the same.
* Run `litradar tag` after every ingest, or wire it into the pipeline.

| Anthropic structured outputs - https://platform.claude.com/docs/en/build-with-claude/structured-outputs | same | `params.output_config = {"format": {"type": "json_schema", "schema": {...}}, "effort": "low"}`; objects need `additionalProperties: false` and `required`; the JSON arrives in the first `text` block; check `stop_reason` (`refusal`, `max_tokens`) before parsing; `effort` sits inside `output_config` and thinking tokens count against `max_tokens` |

The translation path is exercised offline against a fake client (batch success, refusal, truncation,
API-side `errored` result, unknown `custom_id`, a batch that never ends, a zero-second poll against the
wall-clock deadline, exceptions from `batches.create` / `retrieve` / `results` and from the client
constructor, the synchronous path, malformed JSON, missing SDK). **It has not been run against the
real API** - no credentials were available in the build or review environments. The first real run
should be small - `litradar tag --since 7d --translate` - followed by
`SELECT paper_id, lang, substr(title_en,1,80) FROM translations LIMIT 5;`.

## Measured on a real database

One week of papers (3,562 records, 2026-10-10 .. 2026-10-17), `litradar tag --since 365d` against a
read-only backup-API copy: **2.4 s** for the whole corpus, no network.

* **Languages**: `en` 3,562. That window's sources (bioRxiv/medRxiv, Europe PMC, Crossref, OpenAlex,
  arXiv, journal RSS) carry English metadata even for work done elsewhere - the database contained no
  title or abstract with any CJK or Cyrillic character at all. The language field earns its keep once
  Chinese-language and other national-journal adapters feed the same store; until then it is a cheap
  invariant, not a finding.
* **Countries**: 2,441 of 3,562 papers (69%) got at least one country.
  Top of the distribution (a paper counts once per distinct country):
  US 990, CN 365, GB 209, DE 208, FR 175, CA 111, JP 97, NL 81, AU 69, CH 69, IN 68, ES 65, IT 64,
  SE 51, DK 40, KR 40, BR 33, AT 31, BE 31, IL 27, NO 25, HK 25, FI 20, SG 20, PL 18, TR 17, RU 16,
  PT 15, ZA 15, IE 14 - 101 countries in all, with 1,121 papers unresolved (`??`).
  By dominant country only: US 887, CN 338, GB 146, DE 133, FR 123, JP 81, CA 76, IN 55, AU 52.
* **Effect of the gazetteer corrections** (same database tagged before and after, compared paper by
  paper): 6 papers changed, 0 language changes, every change the removal of a false positive -
  `BO` from "La Paz, Baja California Sur" (twice) and "Hospital Universitario La Paz, Madrid", `ES`
  from "Hospital Universitario ... Monterrey, MEX", `GB` from two "London, Ontario" papers, `US` from
  "Santa Cruz, Galápagos Islands, Ecuador" and from "Baja California" (previously matched as
  California; now `MX` via the state name). Coverage is unchanged because none of those papers
  depended on the removed code alone.
* **Where the unresolved ones come from**: Crossref 475, journal RSS 355, bioRxiv 200, arXiv 48,
  medRxiv 23, Europe PMC 20. Those are records that carry **no affiliation data at all**, not records
  the lookup failed on - Crossref deposits affiliations only when the publisher supplies them, and RSS
  and arXiv items carry none. Coverage is therefore a data-availability ceiling, not a gazetteer
  ceiling; the fix is the OpenAlex `country_code` wiring below, not more city names.

## Wiring (what is applied, what is optional)

This module is self-contained; nothing below is required for `litradar tag` to work. Of the four snippets,
**2 is applied** (`Pipeline.post_process()` tags every run); 1, 3 and 4 are optional and not applied.

**1. Keep OpenAlex country codes (not applied; `litradar/sources/openalex.py`, in `to_paper`).** The adapter
currently drops `country_code`. Two small edits give `country_of` exact codes instead of string
matching, and are the single highest-value change for coverage:

```python
# in the authorship loop, add country_code to each institution dict:
insts = [{"name": i.get("display_name"), "type": i.get("type"), "ror": i.get("ror"),
          "country_code": i.get("country_code")} for i in (a.get("institutions") or [])]

# in the Paper(..., extra={...}) block, add:
"institution_countries": sorted({i["country_code"] for a in authors for i in a.institutions if i.get("country_code")}),
```

Also add `"countries"` to the module-level `SELECT` list if you prefer OpenAlex's per-authorship
convenience field over the per-institution one.

**2. Tag at the end of each weekly run - applied.** `Pipeline.post_process(since, until, started)` in
`litradar/pipeline.py` calls `i18n.tag_store(self.store, updated_since=started)` and records
`counts["i18n.tagged"]`; a failure is reported as `i18n: …` in the run's error list and never costs the
run. `started` is the timestamp `run()` takes on its first line, so `updated_since=started` re-tags
exactly the rows this run inserted or re-upserted - including re-fetched papers whose tags the upsert
just erased, whatever their publication date. The equivalent one-liner, for reference:

```python
from .i18n import tag_store            # at the top of the file with the other imports
...
        self.counts["tagged"] = tag_store(self.store, updated_since=started)["tagged"]
```

Translation is **not** wired into the run. To translate in the same pass (only when a key is configured),
add after it:

```python
        from .i18n import translate_titles
        tr = translate_titles(self.store, since=since, until=until,
                              model=self.settings.llm_model, api_key=self.settings.anthropic_api_key)
        self.counts["translated"] = tr.get("translated", 0)
        if tr["status"] not in ("ok", "skipped"):
            self.errors.append(f"translation: {tr['status']} {tr.get('error') or tr.get('processing_status') or ''}".strip())
```

`translate_titles` never raises for API, network or model failures and never imports the SDK when
no key is set - check `report["status"]` (`ok` / `skipped` / `incomplete` / `error`), as above. The
only thing that raises is a key being set while the optional `anthropic` package is missing.

**3. Show it in the digest (not applied; `litradar/digest/render.py`, inside `render`).** Add the section wherever
it fits the narrative, e.g. after the instruments table:

```python
    from ..i18n import histograms
    hist = histograms(store, since, until)
    md.append("\n## Where the work came from\n")
    if hist["untagged"]:
        md.append(f"_WARNING: {hist['untagged']} of {hist['papers']} papers in this window are untagged "
                  f"(new or re-ingested since the last tag); run `litradar tag`. Counts below under-count._\n")
    md.append(_table(["Country", "Papers"], [[c, n] for c, n in list(hist["primary_countries"].items())[:20]]))
    if {k: v for k, v in hist["languages"].items() if k != "en"}:
        md.append(_table(["Language", "Papers"], [[k, v] for k, v in hist["languages"].items()]))
```

and, to show English titles for non-English papers in the top list:

```python
    tr = translations_for(store, [p["id"] for p in top])     # from ..i18n import translations_for
    # inside the per-paper loop:
    t = tr.get(p["id"])
    if t:
        md.append(f"_{t['lang']} → EN: {t['title_en']}_  ")
```

**4. Optional config (not applied; `config/radar.yaml`).** Nothing is read from YAML today; if you want the weekly
run to be switchable, add and read it in the pipeline wiring above:

```yaml
i18n:
  tag: true           # write lang + countries into papers.extra_json each run
  translate: false    # translate non-English titles with Claude (needs ANTHROPIC_API_KEY)
  max_translate: 1000
```
